# 日复盘模板

生成日复盘时严格按此结构输出。

## 模板

```markdown
## 📆 {M.DD} 日复盘

### 📌 今日三件事
1. 工作：{从工作日报提炼当天最重要的工作事项}
2. 学习：{从生活日记提炼当天的学习内容}
3. 生活：{运动/养生/生活事件，无则写"—"}

### 🔄 KPT
- **Keep**：{今天什么做得好，值得继续保持}
- **Problem**：{遇到什么问题或阻碍}
- **Try**：{明天要尝试什么改进}

### ⏱ 今日精力分布
- 工作：{估算工作投入的时间和精力占比}
- 学习：{估算学习投入}
- 运动/养生：{估算运动养生投入}
- 其他：{休息、生活杂事等}
- **精力状态**：{从日记语气判断今天精力状态，如"充沛"/"平稳"/"透支"}

### 🎯 明日头等大事
1. {从日记中的 TODO/计划提取，或基于 KPT 的 Try 推导}

### ❓ 反思提问
- **方向校验**：{针对用户今天的技术决策或思考方向，判断方向是否合理，提出验证性问题}
- **困惑点挖掘**：{识别日记中认知模糊或犹豫不决的地方，主动调研最新信息，给出具体建议}

### 🔗 今日信息补给（如有）
- {针对困惑点或方向校验，通过 knowledge-forge 抓取的最新社区实践/文章/讨论，附链接}
```

## 生成指南

### 今日三件事
- 从两个日记页面中提取当天最有代表性的 3 件事
- 工作、学习、生活各一件；某个维度当天没内容则合并
- 用一句话概括，不超过 20 字

### KPT 生成
- **Keep**：找当天日记中明确有正面结果或坚持做的事
- **Problem**：找当天提到的困难、失败、未完成的事项
- **Try**：基于 Problem 提出一个具体、可执行的改进动作
- 如果当天日记内容较少，KPT 可以精简，不要硬凑

### 今日精力分布
- 从日记内容推断时间和精力分配，不需要精确到小时，给出大致比例即可
- 精力状态从日记的语气、用词判断（如"太顶了"="透支"、"终于周末"="需要恢复"）
- 如果当天日记没有足够信息推断，标注"信息不足，建议记录时注明时间"

### 反思提问
反思提问分两类，各生成 1 个：

**方向校验**：
- 针对用户当天做出的技术选型、工具选择、学习方向等决策
- 判断方向是否合理，给出依据
- 好的示例："你决定放弃 OpenClaw 调度 CC，转向直接写 SKILL。社区里 @elvis 的方案确实更适合多 Agent 协作场景，而你的小红书工作流是单 Agent 就能搞定的，这个判断是对的。但下一步你有没有考虑过用 Lobster 来编排 SKILL 的执行顺序？"
- 如果当天没有方向性决策，此项可省略

**困惑点挖掘**：
- 识别日记中的犹豫、疑问、"还没想清楚"的地方
- **主动调研**：使用 `/knowledge-forge ingest` 抓取相关的最新文章、推特讨论、社区实践
- 将调研结果整理为「信息补给」，附在复盘末尾，包含链接和关键结论
- 好的示例："你提到 ACP 协议但不确定要不要深入。调研发现社区里 @xxx 分享了 ACP + Lobster 的完整实践，核心结论是 ACP 更适合跨机器调度，本地单机用 tmux 就够了。详见信息补给。"
- 如果当天没有明显困惑，可以从日记中找一个值得深入思考的点

### 信息补给生成
- 当发现用户有技术困惑或方向模糊时，使用 `/knowledge-forge ingest <相关URL>` 抓取最新信息
- 也可使用 `/knowledge-forge query` 查询知识库中已有的相关知识
- 信息补给不是每天都有，只在识别到明确困惑点时才生成
- 格式：标题 + 1-2 句核心结论 + 来源链接
