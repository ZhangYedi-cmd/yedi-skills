# 技术方案模板

基于团队标准模板，v2 增强：复杂度适配裁剪、Off-limits 章节、文件级任务拆分。

## 复杂度适配

| 复杂度 | 条件 | 输出章节 |
|--------|------|---------|
| 精简版 | 1 页面 / ≤1 天 / 改动 ≤3 文件 | 一、三、五（5.1-5.4）、5.5、六 |
| 标准版 | 2-5 文件 / 1-3 天 | 所有章节（四可选） |
| 完整版 | 跨页面 / >3 天 / 跨模块 | 所有章节 + 分期计划 |

## 各章节写作要求

### 第五章是核心

衡量方案质量的标准：
- **事前**：目标明确，产品/测试能获取足够信息，有技术选型思考
- **事中**：尽可能少调整
- **事后**：尽可能少 bug，可扩展可复用

### 详细设计要求

1. 基于实际代码分析，不能凭空设计
2. 改动文件要精确到路径
3. 接口要有请求参数、响应结构（从代码或后端文档获取）
4. 数据结构用 TypeScript 类型定义
5. 包含 UI 交互逻辑的完整描述
6. 边界条件不能遗漏
7. **5.5 Off-limits 必须填写**——告诉下游（task-spec-gen / 子 Agent）什么不能动

### 6.1 任务拆分要求

1. 每个任务对应一组紧密相关的文件
2. 必须列出具体文件路径（不是 "开发功能"）
3. 标注任务间依赖关系
4. 被依赖的任务排前面

### 占位符规则

不确定的信息用 `{待填写}` 标记，不要编造。包括：
- 干系人信息
- Ones 链接
- 接口 URL / 网关地址（⚠️ 必须从代码或后端文档确认）
- 上线时间
