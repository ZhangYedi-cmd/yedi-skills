## 各章节写作要求

### 第五章是核心

衡量方案质量的标准：
- **事前**：目标明确，产品/测试能获取足够信息，有技术选型思考
- **事中**：尽可能少调整
- **事后**：尽可能少 bug，可扩展可复用

### 详细设计要求

1. 基于实际代码分析，不能凭空设计
2. 改动文件要精确到路径
3. 接口要有请求参数、响应结构
4. 数据结构用项目对应语言的类型定义
5. 包含 UI 交互逻辑的完整描述
6. 边界条件不能遗漏

### 占位符规则

不确定的信息用 `{待填写}` 标记，不要编造。包括：
- 干系人信息
- Ones 链接
- 接口 URL / 网关地址
- 上线时间
