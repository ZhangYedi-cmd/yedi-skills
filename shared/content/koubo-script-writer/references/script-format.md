# 口播稿格式规范

## 文件结构

```markdown
# 口播稿：{一句话钩子，不是标题党，是这期内容的真实主张}

> 对应讲义 `{源文档文件名，没有就删这行}`，全稿约 {N} 字，语速 4.5 字/秒约 {M 分 S 秒}。
> 需要压到 {目标时长} 时，先砍【{段落名}】{具体砍哪部分}，再砍【{段落名}】{具体砍哪部分}。

## 【钩子｜约 15 秒】

{连贯口语段落，不分点}

## 【{段落名}｜约 N 秒】

{连贯口语段落}

...

## 【收尾｜约 N 秒】

{连贯口语段落，结尾必须有一个抛给观众的开放问题或行动号召}
```

## 措辞规范

- **第一人称、口语化**。把每一句读出声，读起来卡壁的地方就是要改的地方。禁止"首先/其次/综上所述/由此可见"这类书面语连接词，用"先说.../再说.../所以呢"这类口语过渡。
- **段落内不分点**。口播稿是要连续念出来的，观众听不到 bullet 符号。如果内容天然是列表（比如三条规则），改写成"第一条是...；第二条，也是更容易忽略的一条，是..."这种口语化的顺承。
- **具体案例代替抽象定义**。解释一个概念时，先给一个读者能立刻在脑子里成像的场景/案例，再点出这是什么概念——不要反过来先给定义再举例。
- **数字必须来自素材，不能编**。素材里没有的 benchmark/统计数字，宁可不说，或者说"具体数字我实测过再来告诉你"。这是硬红线，不是风格建议。
- **每段一个钩子往下带**。段落结尾留一个悬念或反问，带动观众听下一段，不要段落之间生硬跳转。

## 时长与字数换算

- 基准语速：4.5 字/秒（普通话正常语速口播，不是新闻联播语速）。
- 目标秒数 × 4.5 = 目标字数，允许 ±10% 浮动。
- 超时长处理优先级：先砍"坑/边界"类补充段落，再砍案例细节里的枝节描述，最后才动核心论点段落——核心论点段落被砍说明大纲设计有问题，应该回头改大纲而不是硬删正文。

## 头部"压缩指引"怎么写

写清楚"如果要缩短，先砍哪、再砍哪"，给出具体的段落名和砍法（不是笼统说"精简一下"）。这行是给"二次剪辑/缩时长"场景用的，写的时候假设执行者没读过全文，要一眼能操作。

## 参考范例

见项目 `content/**/koubo.md` 或历史产出（如 douyin-media 项目里 `docs/share-docs/*-koubo.md`）——如果调用方项目里已经有产出过的口播稿，先读一篇当参考，跟着它的节奏写，不要自创新格式。
