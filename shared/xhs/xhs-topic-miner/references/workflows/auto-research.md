# Auto-Research 工作流

## 使用场景

不依赖指定博主，对整个图鉴内容市场做横向扫描，系统性回答：
- **What**：当前什么图鉴选题在爆？
- **Why**：这些选题为什么能爆（STEPPS 机制诊断）？
- **Gap**：哪些话题有需求但供给不足（蓝海机会）？

## 触发命令

```bash
/topic-miner research                        # 全品类扫描
/topic-miner research --category 传统文化    # 指定品类（调整关键词矩阵）
/topic-miner research --n 50                 # 候选池大小（默认50）
```

## 依赖工具

| 工具 | 用途 | 必须？ |
|------|------|--------|
| `xiaohongshu-mcp.search_feeds` | 搜索笔记（Phase 1） | 是 |
| `xiaohongshu-mcp.get_feed_detail` | 获取笔记详情（Phase 3） | 否（缺失时降级） |

降级策略：
- 无 `get_feed_detail` 时，保留 Phase 1/2/4/5。
- Phase 3 改为「标题与互动数据代理分析」，并在报告中标注 `detail_sampling: skipped`。

## Phase 1：搜索矩阵扫描

**执行者**：调用 `search_feeds` × 8-10 次
**目标**：汇总去重后得到 50 条候选笔记

### 关键词矩阵（三层覆盖）

**Layer A — 形式词**（精准捕捉图鉴体裁，避免收入普通图文）

| 关键词 | 捕捉目标 |
|--------|----------|
| `图鉴` | 所有图鉴内容 |
| `图录` | 器物/文化类图鉴偏好词 |
| `图解` | 科普/原理类图鉴偏好词 |

**Layer B — 内容域词**（覆盖图鉴账号的 5 个 Pillar 方向）

| 关键词 | 对应 Pillar |
|--------|-------------|
| `传统文化 图鉴` | P1 传统智慧 |
| `老祖宗` | P1 传统智慧（爆款标志词） |
| `古代 大全` | P3 文化图录 |
| `节气 花卉` | P2 自然博物 |
| `中草药 养生` | P4 生活指南 |

**Layer C — 爆款信号词**（捕捉不含"图鉴"但在同赛道的高传播内容，防止遗漏）

| 关键词 | 捕捉目标 |
|--------|----------|
| `九大 天规` | 数字+规律型爆款 |
| `排行榜 冷知识` | 榜单型爆款 |

### 搜索参数

```
时间范围：最近 90 天
内容类型：图文（非视频）
每次取量：20 条
执行次数：8-10 次（按三层关键词顺序执行）
```

### 处理规则

1. 合并所有搜索结果
2. 按 `feed_id` 去重（同一笔记可能出现在多个关键词搜索中）
3. 保存字段：`feed_id`、`title`、`liked_count`、`xsec_token`、`author_name`

**完成条件**：候选池 ≥ 40 条（如不足，补充 Layer C 词汇或放宽时间范围至 180 天）

## Phase 2：质量过滤

**执行者**：对候选池逐条评分，满足 2/3 条规则即入选
**目标**：精选池 25-30 条

### 入选规则（满足 2 条即通过）

**规则 1 — 量化信号（互动数据）**

```
点赞数 ≥ 500
OR（点赞数 200-500 AND 收藏数/点赞数 ≥ 0.5）
```

意义：高点赞证明传播力，高收藏比证明内容有持久知识价值（图鉴类内容的典型特征）。

**规则 2 — 结构信号（标题格式）**

```
标题含数字（1-99）+ 量词组合（大/种/个/条/要/律/诫）
OR 标题含关键词（图鉴 / 图录 / 大全 / 合集 / 排行）
```

意义：图鉴体裁的高可靠形式特征，随机内容极少命中。

**规则 3 — 语义信号（内容定位）**

```
标题含权威词（老祖宗 / 古代 / 传统 / 历史 / 本草 / 自然 / 生物）
OR 标题含情绪词（绝了 / 震撼 / 冷知识 / 你不知道的 / 原来 / 竟然）
```

意义：区分「正规图鉴内容」和「随手配图的普通帖子」。

### 一票否决（任意一条 → 直接排除）

- 标题含商业词（推荐 / 购买 / 链接 / 店铺 / 优惠）
- 标题为纯 emoji，无实质文字
- 内容类型为视频

### 输出格式

```yaml
filtered_pool:
  - feed_id: "xxx"
    title: "..."
    liked_count: 1200
    xsec_token: "..."
    passed_rules: [1, 2]      # 命中的规则编号
```

## Phase 3：详情采样（可降级）

**执行者**：对精选池按点赞数排序，取 TOP 10，调用 `get_feed_detail`
**目标**：获取可供语义分析的深度内容（若工具不可用则跳过并标注）

### 从详情中提取的字段

| 字段 | 用途 |
|------|------|
| 正文内容 | 提取高频词，判断内容定位 |
| 评论列表（前 10 条） | 识别传播触发词（"收藏了" / "转发给XX"） |
| 图片数量 | 验证图鉴形式（3-8张是最优区间） |
| 话题标签 | 辅助聚类 |

### 传播触发词识别

在评论中寻找以下信号词，作为「传播触发证据」记录：

```
收藏了 / 已收藏              → 高实用价值信号
转发给 / 发给XXX             → 社交货币信号
震撼到了 / 没想到 / 原来如此  → 高情绪唤醒信号
怎么做到的 / 在哪里买         → 实用需求信号
```

**为什么只取 TOP 10**：API 调用有成本，爆款规律归纳只需代表性样本。TOP 10 已覆盖最有说服力的传播证据。

## Phase 4：模式提炼

**执行者**：对 TOP 10 详情 + 精选池全量数据做跨笔记分析
**核心目标**：不是逐条描述数据，而是归纳机制性规律，给出「为什么能爆」的解释

### 输出结构

#### 4.1 What — 主题聚类

将精选池笔记聚类为 3-5 个主题群，每群输出：

```markdown
### 主题群 [N]：[一句话主题概括]

代表笔记：
- 「[标题]」（[点赞数]赞）
- 「[标题]」（[点赞数]赞）

核心主题：[一句话概括这群内容在讲什么]
典型格式：[数字X + 名词 / 排行榜 / 对比型 / 流程型 / ...]
内容域：[对应 Pillar]
```

#### 4.2 Why — STEPPS 机制诊断

对每个主题群，分析驱动传播的核心 STEPPS 维度：

**分析框架**：

| STEPPS 维度 | 诊断问题 |
|-------------|----------|
| Social Currency | 分享这个内容会让我显得怎样（博学/有品位/有见识）？ |
| Triggers | 什么日常场景会让人想起这个内容？ |
| Emotion | 引发的核心情绪是什么（敬畏/愤怒/惊讶/共鸣）？ |
| Public | 内容是否天然适合被展示/截图/转发？ |
| Practical Value | 对分享者有什么功能性价值（即看即用/购买参考/处世指导）？ |
| Stories | 内容是否有叙事弧度或戏剧冲突？ |

**输出格式（要有机制性结论，不只是打分）**：

```markdown
### Why：[主题群名] 的传播机制

核心驱动维度：[S/T/E/P/P/S 中的 2-3 个]

机制解释：
「[主题群]爆款的核心驱动是 [维度1] × [维度2]——
[维度1 的机制]：[具体解释，100字以内]
[维度2 的机制]：[具体解释，100字以内]
两者叠加的结果：[为什么双维度比单维度传播力更强]」

传播触发证据（来自评论分析）：
- "[高频评论词]" → [说明什么传播行为]
```

**机制性解释示例**（供参考，不要照抄）：

> 「传统智慧类图鉴爆款的核心驱动是 Social Currency × Emotion（敬畏）——
> Social Currency：转发「老祖宗智慧」让分享者获得「博学有文化」的社交标签，尤其在朋友圈/家族群中有强烈的身份展示价值。
> Emotion（敬畏）：古代圣贤智慧的道德权威感触发敬畏情绪，促使读者停留和保存内容。
> 双维度叠加：既满足「分享给别人」（社交货币）的外部动机，又满足「自己收藏」（敬畏触发的行为），导致点赞+收藏双高，算法正反馈。」

#### 4.3 Gap — 需求-供给缺口矩阵

**目标**：找到「有需求但无人满足」的话题

**构建方法**：

1. 从 Phase 1 搜索的关键词联想词中提取候选话题（10-15 个）
2. 对每个候选话题，评估：
   - 搜索需求：该话题在 XHS 搜索补全中出现的频率（高/中/低）
   - 供给密度：现有相关笔记的数量和平均点赞（高/中/低）

3. 缺口评级判断标准：

| 评级 | 供给密度 | 平均赞 | 含义 |
|------|---------|--------|------|
| 🔴 蓝海 | 低（< 10篇） | < 500 | 真蓝海：需求无人满足 |
| 🟡 机会 | 中 | 200-800 | 质量蓝海：有人做但做得差 |
| 🟢 红海 | 高 | > 1000 | 已有强竞品，需差异化 |

**输出格式**：

```markdown
### Gap：需求-供给缺口矩阵

| 话题方向 | 搜索需求 | 供给密度 | 平均赞 | 缺口评级 | 机会类型 |
|----------|---------|---------|--------|---------|---------|
| 传统人物图鉴 | 高 | 低 | <500 | 🔴 蓝海 | 开创型 |
| 节气花卉搭配 | 高 | 低 | <300 | 🔴 蓝海 | 时效型 |
| 古代兵器图鉴 | 中 | 中 | 600 | 🟡 机会 | 质量提升型 |
| 凶花图鉴 | 高 | 高 | 2000 | 🟢 红海 | 差异化 |

蓝海话题小结：
1. [话题]：[一句话说明为什么是机会]
2. [话题]：...
```

## Phase 5：选题生成

**执行者**：对 🔴 蓝海话题应用标题公式 + STEPPS 评分
**目标**：生成可直接写入 backlog.yaml 的候选选题

### 第5条生成路径：Gap-Driven（需求-供给缺口驱动）

区别于现有4条路径，gap_driven 路径的选题来自市场缺口发现，而非竞品延伸或AI发散。

**生成逻辑**：

```
对每个 🔴 蓝海话题：
  1. 组合爆款标题公式（参考 title-formulas.md）
  2. 生成 3 个标题变体（侧重不同 STEPPS 维度）
  3. 用 STEPPS 模型预评分
  4. IF score ≥ 3.8 → 写入 backlog.yaml（source: gap_driven）
  5. IF score < 3.8 → 标注为「待优化」，给出分数最低维度和改进方向
```

### backlog.yaml 新字段

gap_driven 选题在标准字段基础上新增 `gap_evidence`：

```yaml
- id: "research-001"
  title: "..."
  alt_titles: [...]
  pillar: P1_传统智慧
  bucket: B1_大全
  variant: natural-history
  layout: center-radial
  source: gap_driven                  # 第5条路径标识
  gap_evidence:                       # 缺口证据（仅 gap_driven 有此字段）
    search_demand: high               # 搜索需求：high/mid/low
    supply_density: low               # 现有供给密度：high/mid/low
    top_competitor_likes: 0           # 现有最高赞竞品点赞数（0=无竞品）
    gap_type: "蓝海"                  # 蓝海/机会/红海
  stepps: {S: 5, T: 3, E: 5, P_pub: 4, P_prac: 3, S_story: 5}
  score: 4.30
  tier: Hero
  status: idea
  reasoning: "..."
  created: "YYYY-MM-DD"
```

### 输出文件

**报告**：`topic-miner/research-{YYYY-MM-DD}.md`

结构：
```
# 市场调研报告 — {YYYY-MM-DD}

## 数据概况
- 搜索批次：X 次
- 候选池：X 条
- 精选池：X 条（过滤后）
- 详情采样：TOP 10

## What：市场热门主题聚类
[Phase 4.1 输出]

## Why：爆款规律诊断
[Phase 4.2 输出]

## Gap：需求-供给缺口矩阵
[Phase 4.3 输出]

## 生成的选题（已写入 backlog.yaml）
[每条选题的简要列表]
```

**backlog 更新**：直接追加到 `topic-miner/backlog.yaml`，status 初始为 `idea`。字段约束见 `references/config/backlog-schema.md`。

## research vs analyze 模式对比

| 维度 | analyze | research |
|------|---------|----------|
| 输入 | 指定博主 URL | 无需输入（或指定品类） |
| 数据范围 | 单博主（31-100篇） | 跨账号市场（50篇） |
| 洞察类型 | 该博主做了什么 → 我能延伸什么 | 整个市场做了什么 → 哪里有空白 |
| 选题来源 | competitor_extend / matrix_fill | gap_driven |
| 适合场景 | 已知竞品，深度学习 | 发现蓝海，主动出击 |

**两种模式可互补**：先 `research` 找方向，再 `analyze` 学做法。
